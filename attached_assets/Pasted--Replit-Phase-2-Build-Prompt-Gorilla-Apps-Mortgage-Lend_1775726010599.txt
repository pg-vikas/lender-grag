# Replit Phase 2 Build Prompt — Gorilla Apps Mortgage Lender Super Admin

Build **Phase 2** of the **premium dark mode mortgage lender Super Admin platform** inside **Gorilla Apps**.

Phase 1 already established the foundation:

* app shell
* dashboard
* CRM
* leads
* borrowers
* loan pipeline
* borrower detail pages
* loan detail pages
* global search
* quick create
* shared drawers

**Phase 2 is where the platform starts becoming operationally dangerous.**
This phase should add the lender workflows that actually move files, collect documents, secure signatures, manage borrower communications, and keep the team on task.

## Phase 2 goal

Build the operational execution layer with these modules:

* Documents
* E Sign
* Conditions
* Communications
* Tasks
* deeper timeline integration across borrower and loan files
* reusable status systems and workflow components

This phase should make Gorilla Apps feel less like a CRM and more like a **real mortgage operations system**.

---

## Core objective for Phase 2

A lender using this build should be able to:

* request borrower documents
* track document status clearly
* review uploaded items
* send e sign packages
* place signature and form fields on PDFs
* manage underwriting style conditions
* communicate with borrowers from one place
* see a cleaner unified timeline of file activity
* assign and complete tasks tied to a file or borrower

This is the phase where internal operations start becoming real.

---

## Visual direction

Maintain the same design system as Phase 1.

### UI character

* dark mode first
* premium
* structured
* operationally sharp
* dense but readable
* visually forceful without clutter

### Accent behavior

Use color to signal state and urgency:

* blue / cyan for active work
* green for cleared or completed states
* amber for pending review
* red for urgent, missing, failed, or rejected states
* magenta or Gorilla pink for core product branded actions

### Do not do

* bloated enterprise UI
* weak washed out dashboards
* giant blank areas
* childish iconography
* generic admin template styling

Assume this phase connects cleanly to the Phase 1 architecture.

Build Phase 2 like the **execution engine** of a mortgage operating system.

The user should now feel that Gorilla Apps can actually move a file through real operational steps, not just display CRM data.

Make documents, e sign, conditions, communications, and tasks feel tightly connected.

This phase should make the platform feel commercially credible, operationally useful, and visibly more powerful than a generic lender CRM.
